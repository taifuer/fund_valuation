# 长期走势与年度收益

入口为「走势 → 长期」，路由 `/history`。范围包括配置中的全部主要指数和资产，目前为19个指数、4个资产，不限于最初举例的标普500、纳斯达克、纳指100、黄金和比特币。

「近期」按日线比较最新、今年和近1周至近5年表现；「长期」按月线观察近5/10/20/30年及全部历史，并列出年度收益。两者按用途与采样频率区分，不以3年或5年作互斥分界；日频与月末回撤不能直接等同。详情弹窗与近期汇总的近5年均按日历周年取基准，处理闰日；近期缺少起点或出现超过20个自然日的明显数据中断时，不冒充完整5年结果。

## 日线补齐

`backend/daily_archive.py` 由 worker 每30分钟执行，默认最多4个串行请求，优先补足5年，再向更早时间延伸。A股指数、ETF、恒生使用腾讯按日期窗口请求，最多两个日历年，避开最近1023条限制；纳斯达克、纳指100和日经225使用 FRED 的 `NASDAQCOM`、`NASDAQ100`、`NIKKEI225` 原始日线，韩国沿用 Naver，台湾按官方月份逐月回填。不用月线插值，不拼接现货与期货。尚未初始化的日线仍由原有历史任务负责。

补充源必须与原序列至少3个重叠日核对，价格差异超过0.1%、空响应、重复日期、非法价格或日期窗口不匹配均拒绝写入。ETF只接收未复权价格，继续由既有分红/拆分因子计算收益。只插入缺失日，不覆盖已有收盘。日经近期日线仍由官方文件更新，较早档案通过 FRED 与官方重叠区间核对后补齐；2026-09-19已从线上网络验证FRED可访问，Yahoo同次探测返回429，未加入自动补齐任务。

进度保存在 SQLite `market_history_backfill`（迁移15），诊断覆盖报告包含补齐状态。请求失败6小时后重试，并重新验证上游而非继续使用无效响应缓存；价格冲突记录为 `review`，30天后复核，不通过放宽容差拼接。有效响应没有更早数据时记录「来源边界」，30天后复查，不将它标为“成立以来完整”。常规页面只读数据库，不触发补齐。跨进程API缓存最多等待原有TTL（市场汇总30分钟）刷新；原始响应缓存键包含请求URL摘要，切换来源不会读到旧源缓存。

```bash
npm run backend:archive -- --max-requests 4
npm run backend:archive -- --item sina-cn:sh000001 --max-requests 1
npm run backend:archive -- --item nikkei-index:N225 --retry-failed --max-requests 1
```

历史数据必须同时核对来源、价格口径与内部缺口，不能仅凭最早日期证明全部完整。基金净值继续使用原有按总记录数校验的分页补齐任务；不足5年的新基金不补造成立前记录。

2026-09-19本地验证：A股、ETF、恒生等首两轮补入15,604条日线，日经另补入2021和2022年共489条日线，近5年已可计算。纳斯达克2004年与纳指100在2014年的FRED重叠记录存在差异，未覆盖也未拼接；标普500、道琼斯更早日线尚未纳入自动补齐。已有长期月线保持独立，不宣称所有标的已拥有发布以来的完整日线。

## 呈现与口径

- 默认显示单标的月末价格折线与年度收益表；支持近5年、近10年、近20年、近30年、全部，以及线性 / 对数刻度。布局与控件复用收益/风险页的基础样式；移动端类别独占首行，下一行左侧切换视图、右侧用下拉框选择区间，桌面保留分段按钮。纵轴使用带千分位的完整数字，自动预留标签宽度，不使用 k/M 缩写。
- 默认标普500、全部历史和对数刻度。几十年的价格跨越多个数量级，对数刻度更便于观察相对变化；存在非正价格时不可使用对数刻度。
- 图表支持鼠标、触摸和键盘选点，选点后显示淡色横竖辅助线；历史缺月断线，不插值伪造记录。来源名称统一放在页面末尾，逐点原始链接仍保存在数据库/API中，但不直接展示。
- 图表与年度表只纳入完整日历月。例如2026年9月查看时，两者均截至8月；不混入9月盘中价格或未完成的月线。日期默认显示到月份，原始精确日期保留在提示中。
- 年度表默认最近10年，可展开全部年份；缺少完整基准显示原因而非零收益。移动端只让表格横向滚动，页面本身不溢出。
- 去掉年度旁的「今年」标签与常规加载文字；加载时保留稳定空间及无障碍繁忙状态，真正无归档数据或请求失败时仍显示状态与重试入口。
- 使用「有记录以来」而非「成立以来」。来源最早记录、指数发布日期与回溯计算起点不一定一致。

「涨幅」的近5/10/20/30年比较由完整自然年组成的多年区间，不是选择单个年份。以2026年为例：近5年为2021–2025，近10年为2016–2025，近20年为2006–2025，近30年为1996–2025；计算使用起始年前一年末作为基准，不混入2026年的未完整年度数据。缺少固定区间基准的标的留空、不缩短区间。

「全部」替代原共同区间，使用各自最早可用月末到最新已完成月份，不丢弃较长序列。表格最右侧「区间」逐行注明起止月份，不再在表格上方或名称下方重复显示。由于跨度不同，累计涨幅不能解释为同期间的表现比较；年化也不能消除不同市场、不同历史阶段的差异。

表格列为排名、名称、累计涨幅、复合年化涨幅、回撤、起止值、区间，涨幅、年化和回撤支持表头排序，前三名复用收益页金银铜样式；缺少所选指标时不编号。回撤按跌幅绝对值排序，首次点击为大到小，不以负数的数值大小误排；采用中性文字，不使用涨跌颜色。起止值用独立一列显示「基准收盘 → 期末收盘」，采用中性灰色小字和等宽数字，紧凑相连、整组右对齐，不着涨跌色、不增加行高；列宽按数值长度预留，过宽时仅表格横向滚动。两端来自后端计算使用的原始值，不从已舍入的百分比反推，也不使用实时价。缺失端显示 `--`，真实零值、负值仍保留；旧快照缺少字段时留空，等待下一次快照发布，不增加逐标的请求。

涨幅、年化涨幅和回撤使用右上角小 `*`，不在标题中重复「月末」等口径。底部按指标各用一个独立段落说明，以「* 指标名：」对应，手机自然换行；通过 `aria-describedby` 关联说明，不新增弹窗或点击入口。

固定范围显示例如「2021-01 至 2025-12」，实际计算起点是2020年末。美元资产的起止值共用一个前缀 `$`，指数末尾显示「点」；悬停统一按「基准：…；期末：…；单位：…」呈现，美元单位为「美元 USD」。其他单位原样显示，未知单位不猜测币种。移动端首先保留排名、名称和涨幅，横向滚动查看年化、起止值和区间；日期用灰色小字、右对齐。走势仍按最近完整月份显示滚动区间，两种视图切换时保留近5/10/20/30年选择，各自显示真实统计日期；点击名称返回走势。年末数据滞后的标的不参与排名，不拖慢全榜单，也不把跨年时尚未结束的海外年度当成完整年份。

百分比消除了价格单位差异，但没有消除币种、分红和连续期货口径差异，所以统一称「价格涨跌」而非可投资组合回报。价格指数与总回报、币种应分开处理，可参考 [MSCI指数数据分类](https://app2.msci.com/products/index-data-search/)；这里不新增汇率折算、股息假设或ETF替代。

### 来源限制

- 腾讯公开行情接口没有可依赖的长期服务承诺；成功响应仍校验日期、有限价格及重叠区间。不同来源同一收盘日偏离超过1%时拒绝该批次，保留旧记录。
- 上证指数1993年前的腾讯记录与[上交所统计年鉴](https://www.sse.com.cn/aboutus/publication/yearly/documents/c/10061088/files/02828bf648f9437c9468c28ee3858d3f.pdf)不符，已隔离。东方财富未复权月线通过已有区间的重叠校验，并额外核对1990/1991/1992年末127.61、292.75、780.39，补入25个月；深证成指补入21个月。不根据年度年鉴插值构造月线，不更改已有效的月份；只允许核验后的来源替换明确隔离的早期腾讯记录。
- [标普官方](https://www.spglobal.com/spdji/en/indices/equity/sp-500/)正式发布日在1957年，之前序列注明为回溯历史；价格指数不含股息再投资。
- [日经官方](https://indexes.nikkei.co.jp/nkave/index?type=download)月线用月首日期标识该月收盘，入库只保留月份精度，不伪造实际交易日期；可获取的日线覆盖后保留精确日期。原有日经期货代理不会混入此页面的现货历史。公开获取不等于无限制再分发，生产使用仍需遵守来源许可。
- [台湾证交所](https://www.twse.com.tw/en/indices/taiex/mi-5min-hist.html)此接口从1999-01-05开始，逐月补齐并支持中断续传。KOSPI的部分月线标签并非交易日，同样保留月份精度。
- 黄金、白银、原油仍是期货连续报价，不是现货、ETF或可投资策略回报；换月会影响价格。黄金、白银历史页已整体换为Yahoo日线来源，首页及短期收益/风险页仍保留原有新浪行情链路，两者可能因合约和报价口径不同而不一致。来源差异不能仅靠价格接近就视为同一条可投资序列。
- [Coin Metrics](https://docs.coinmetrics.io/resources/faqs)比特币交易记录从2010年7月开始。使用USD、UTC日线，不为2009年补零价格。
- 可选补全命令使用[FRED纳斯达克](https://fred.stlouisfed.org/series/NASDAQCOM)、[日经](https://fred.stlouisfed.org/series/NIKKEI225)月度期末值及Yahoo月线，至少核对12个重叠月份，任一月份偏离超过1%就拒绝该来源，不覆盖已有有效月末价格。月度标签不代表月首交易价，不使用月均价或调整后价格替代收盘。FRED首个不完整起始月可能被聚合接口省略，因此另取该月的小段日线。
- Yahoo黄金/白银与新浪序列在重叠月份存在偏差，因此不作前后拼接，而是在完整校验后一次替换黄金、白银的整套月度档案。台湾加权早期候选序列仍有冲突，未拼接。道琼斯等更早历史、黄金和白银2000年前的同口径数据仍待补全。
- 新来源只供独立维护命令使用，不进入页面或常规worker的请求链。东方财富历史补充复用现有专用抓取器及30天原始响应缓存，失败保留已有月线。该源本次曾成功返回完整档案，后续探测也遇到连接中断，不能视作稳定性保证。FRED、指数公司等存在来源许可及再分发限制，公开可下载不等于可自由再发布；部署前还需核实网络可达性和适用许可。

### 贵金属离线档案与候选源

- 新浪 `GC`、`SI` 代码无误；本次日线接口只返回2016-09-16起的十年窗口，传入更早日期或更大条数没有扩展。旧库存有2016-07起的记录，说明持续归档可以保留已退出接口窗口的月份，但不能凭空恢复未抓过的年份。
- Yahoo `GC=F`、`SI=F` 日线均覆盖2000-08起。直接请求月线会遗漏部分月份，黄金月线还与日线最后一笔收盘不一致，因此统一以日线的 `close` 归并月末，不用 `adjclose`、月线或前值插值补齐。
- `--metals` 串行下载全量日线及起始段、2020年差异段、最近13个月的独立日线请求，要求至少12个月末一致（容差0.1%），再核对标的、USD、期货类型、首尾月份、重复日期、缺月、非正/非有限值和原档案覆盖。此校验保证请求与聚合一致，不等于独立审计交易所原始数据。首次整体替换新浪月度值；之后同源历史修订超出容差、响应变短或请求失败均拒绝覆盖。原始响应与逐点来源留存；检查失败命令返回非零退出码。
- 常规worker不抓取也不合并黄金、白银长期档案；显式维护命令按月执行即可。页面只读发布快照，首页实时行情和原有日线库不变。部署时可搬运已核验的离线档案，无须在线页面访问Yahoo；不要用整库覆盖线上基金和实时数据。
- [珀斯铸币厂](https://www.perthmint.com/invest/information-for-investors/metal-prices/historical-metal-prices/)提供美元报价的早期公开CSV。本次实际下载黄金、白银日档案和月档案，表头为现货买卖报价的High/Low/Average，没有可直接等同于期货月末收盘的列，因此保留为候选，不接入收益计算。
- [世界黄金协会](https://www.gold.org/goldhub/data/gold-prices)提供1978年起的均价；均价不能替代区间端点。历史LBMA基准数据涉及ICE授权，不绕过许可获取。
- [CME Continuous Price Series](https://www.cmegroup.com/market-data/cme-group-continuous-price-series.html)有明确的期货连续序列口径，但其黄金、白银公开说明起于2010年；更早合约资料可通过DataMine授权渠道获取，不适合为了本次补齐引入账号和付费依赖。
- Stooq 的期货与现货CSV请求当前均返回验证页，未绕过验证，也未当成CSV入库。长期档案不要求实时，但仍需要统一价格口径、可追溯来源及适用的数据使用权限。
- [世界银行 Pink Sheet](https://www.worldbank.org/en/research/commodity-markets)可供长期商品价格研究，但其月均价不作为本页区间端点。[英格兰银行目录](https://www.bankofengland.co.uk/boeapps/database/FromShowColumns.asp?CategId=6&FromCategoryList=Yes&HighlightCatValueDisplay=Gold+price&NewMeaningId=RGOLD&Travel=NIxAZxI4x)列有 `XUMLGPD` 美元黄金月末价；本次CSV请求遇到TLS连接中断，未验证完整覆盖、更新状态与使用权限，未入库，也不把现货基准直接拼入黄金期货序列。

## 计算与边界

```text
完整年度价格涨跌 = (本年末收盘 / 上年末收盘 - 1) * 100%
今年价格涨跌     = (最近完整月份的月末收盘 / 上年末收盘 - 1) * 100%
区间价格涨跌     = (终止月收盘 / 起始月收盘 - 1) * 100%
复合年化涨跌     = ((终止月收盘 / 起始月收盘) ^ (12 / 月份间隔) - 1) * 100%
月末最大回撤     = min(月末收盘 / 该区间截至当月的最高月末收盘 - 1) * 100%
```

- 「回撤」只按同一历史档案的连续完整月末计算，底部星号说明口径；不包含月内波动，不等同于日频或盘中最大回撤，也不混入其他来源的日线。走势摘要对应所选范围，选择全部才是有记录以来；年度表在涨幅右侧逐年显示，以上年末为新基准、不继承更早高点。首段从最早可用月末开始，当年只到最近完整月份。
- 起止缺失、中间缺月、不足两个连续月末、非正/非有限价格或年度边界未完成时，回撤返回空值和原因；完整不跌的序列才返回0。缺月不影响独立有效端点的涨幅计算。回撤由后台发布快照时预计算，页面不补历史、不增加请求。旧快照没有回撤字段时显示 `--`，下次worker发布后可用，也可用 `--publish-only` 离线重建。
- 完整年度分母不是本年第一个交易日，否则会漏掉该日涨跌。首年缺少上年末基准时，以首个可用月末为起点计算至当年末，标注「首段」及起始月份，不称完整年度或上市首日以来收益。仅有一个月末记录、缺少年末或出现非正价格时仍留空；不能编造创始日价格。首段后续年度继续以上年末为基准，表头统一为「基准收盘」。
- 单标的年化对应图表实际显示的起止月份，不是各年度收益的算术平均。月份间隔不等于记录条数，例如2023-08至2025-08为24个月，100变为121，区间上涨21%、年化上涨10%。区间不足12个月不显示年化，起止月缺失、非正价格或非有限值不计算比例涨跌。
- 中间缺月会在曲线上断开，但独立可核验的起止月仍可计算区间涨跌和年化；不把「没有每日记录」误当成「没有时间经过」。连续期货的年化价格变化不是长期持有收益。
- 月度库保留每月最后有效收盘，读取和发布均排除当前月份。旧库中已写入的当月记录不会出现在图表或年度计算中。官方完整月末记录即使仅有月份精度，也可作为年末基准，月均价不可以。
- 完整月末标记随来源原始抓取时间保存，跨入新月不把旧的未完成月线直接视为完成。已确认的完整月末可以覆盖跨年连休造成的提前收盘。
- 日线归并取原来源最后有效记录；存在后续月份观测且距离月末不超过7天时容许假期提前结束。这是对已有日线归档完整性的假设，不是对每个历史交易日历的认证。没有后续观测或完整月线确认时采用最后工作日检查，拒绝月中停止更新的记录。比特币始终要求UTC日历月末。
- 无完整月末确认的年末记录额外考虑日经12月31日休市和KOSPI年末休市；不能把12月任意一日当作完整年末。
- 北京时间跨入新年时，美股或比特币的上一年可能尚未结束，不提前结算为全年收益。各市场今年的截至日期可以不同，不使用盘中期货补现货。
- 中间缺月不会抹掉有独立年末基准的年度收益；价格非正、年末基准缺失或异常时返回空值及原因，不填0。

## 存储与维护

- SQLite迁移14新增 `long_market_history` 和 `long_history_sync`，按标的和月份幂等写入，短响应不删除更早记录；原有日线、基金净值及估算链路保持不变。
- `backend/long_history.py` 负责串行回填、来源校验和年度快照。先发布已有历史，再逐项补全；接口不触发上游请求。
- worker每30分钟维护一次，每批最多检查2个标的；同一标的至少间隔24小时，上游原始响应缓存24小时。台湾每批最多2个月，首次完整补齐建议单独运行下列命令。
- `/api/longhistory` 读取目录及 `comparisons` 预计算的各类别、多年自然年区间排名；`?symbol=INX` 读取单个序列及区间摘要。涨幅视图只需一份目录快照，不逐一请求全部标的历史。计算与发布在worker中完成，不增加上游请求或独立服务。
- 准备中返回202，正常快照支持ETag和5分钟缓存。新路由按需加载，不加载基金估值、持仓或大盘实时行情；`view=change`、`range=5` 和所选类别均保留在URL中。旧快照缺少新范围时显示待更新而不是误报暂无同区间数据；手动重试跳过内存缓存并重新验证浏览器缓存。

```bash
npm run backend:history -- --twse-months=360
npm run backend:history -- --extend
npm run backend:history -- --metals
npm run backend:history -- --us-indices
npm run backend:history -- --oil

```
