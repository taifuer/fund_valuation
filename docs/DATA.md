# 数据与估算

长期走势与自然年度收益位于 `/history`，覆盖当前主要指数和资产。月度价格独立存储，图表和年度表均只纳入完整月份，年度计算使用上年末基准；日经采用现货历史，商品连续期货明确注明口径，不混入原有风险或基金估算。覆盖范围、来源及缺数处理见 [长期历史](./LONG_TERM_HISTORY.md)。

## 市场行情口径

- A 股在交易时段展示实时行情；美股按北京时间晚间交易时段展示实时行情
- 港股和亚太指数非交易时段展示最近有效收盘价
- 纳指100、标普500、道琼斯、恒生指数和日经225现货闭市且对应期货活跃时，可在概览展示“期货 LIVE”参考
- 收益与风险页面使用已完成交易的现货或历史日线，不以盘中期货替代现货区间收益
- 市场状态结合交易所本地时区、午休、周末和已维护节假日判断

期货与现货存在基差、分红、利率、汇率和换月影响，只适合判断闭市期间方向，不等同于现货指数涨跌。

## 历史收益口径

收益页“近期”支持点击名称或整行查看日线走势，弹窗沿用列表区间；“最新”默认打开近一个月。历史区间按列表截止日期查看，收盘历史不混入盘中实时点。图表按需读取已有历史，不触发页面请求时补抓；基金仅加载官方净值，不加载持仓或估值。关闭后保留筛选、排序、滚动位置。

日经225近期收益及概览历史图统一使用[日经官方日线](https://indexes.nikkei.co.jp/nkave/historical/nikkei_stock_average_daily_jp.csv)，以 `nikkei-index:N225` 独立存储，旧 `sina-futures:NK` 数据保留但不再用于指数走势或收益。2026-09-19 核查该文件从 2023-01-04 开始；更早月度数据仍在“历史”视图，不用月线或期货拼接日线。部署后由 worker 补齐新源，未就绪时不回退期货。

- 未获取到官方日涨跌幅时保存为空，不当作 `0.00%`；净值明细仍保留该日。
- 基金折线保留官方单位净值。区间收益、回撤和胜率使用分红调整后的连续收益序列；普通交易日采用净值比，分红日结合累计净值与官方日涨跌处理。分红视为再投入，不直接用累计净值相除。
- 场内 ETF 由 worker 保存新浪 `hfq.js` 的拆分比例与累计现金分红，按真实调整事件连接收益。拆分当日仍保留真实市场涨跌，不能把异常跳变日强行改为零。
- 无法核实的显著价格断点会切分序列；跨断点区间不输出收益和风险指标，待调整数据补齐后恢复。未发生大幅跳变不代表已完整覆盖所有分红事件。
- 最新交易日采用交易所本地日期；报价时间统一为北京时间。估值对应收盘时间与后台计算时间分开保存。

## 基金估算日期

估算先确定目标净值日，并保证价格和汇率按同一日期对齐：

- **待公布估值**：选择相关持仓市场均已完成交易的最近境内估值日，持仓收盘价与汇率冻结在该目标日
- **实时参考**：使用当前境内估值日；已收盘市场采用当日收盘，交易中市场采用当前行情，尚未开盘市场沿用最近收盘

最新官方净值、待公布目标日和实时参考目标日分别保存，避免将不同时点的数据混成一次估算。

## 计算公式

```text
股票累计涨跌 = 目标日价格 / 官方净值日价格 - 1
汇率累计涨跌 = 目标日汇率 / 官方净值日汇率 - 1

持仓人民币口径涨跌 = (1 + 股票累计涨跌) * (1 + 汇率累计涨跌) - 1
已披露持仓贡献 = sum(持仓权重 * 持仓人民币口径涨跌)

估算累计涨跌 = 已披露持仓贡献
             + (股票仓位 - 已覆盖权重) * 基准人民币口径涨跌
目标估算净值 = 最新官方净值 * (1 + 估算累计涨跌)
目标日涨跌 = 目标估算净值 / 上一估值日估算净值 - 1
```

默认基金按投资方向配置纳指100、标普500或对应宽基，补足未披露仓位。汇添富全球医疗（004877）使用全球医疗、恒生生物科技和低波动部分组成的复合代理；必要历史不完整时暂停生成估值，不用前十大持仓简单归一化替代。

股票仓位默认取 1。只有同一报告期的资产配置可核实、且不小于披露持仓权重时，才使用披露股票仓位，其余部分暂按零收益处理；这仍不能精确模拟债券、外币现金与费用。复合代理已包含低波动部分时，不重复应用这一修正。数据口径不一致则保持原口径，并在持仓详情说明。

持仓检查请求最多 1000 条披露记录，半年报、年报提供扩展持仓时优先保存；季度仅披露前十的仍按前十使用。同一期较少条目的响应不得覆盖已有扩展持仓。记录报告期、权重、来源、内容版本与检查时间，超过 200 天的旧持仓不再生成估值。扩展披露不代表当前实时持仓，也不保证每一项都能取得行情。

## 校准与回测

worker 保存待公布估值快照，官方净值披露后记录误差。校准样本必须属于同一模型、同一季度持仓、同一残差基准和同一输入集合；仅在完整样本达到门槛，且时间外验证 MAE 至少改善 10% 时，才启用受限线性校准，否则保持原始模型。

## 公司经营数据

公司页面用于观察同一企业自身变化，不做跨币种绝对规模排名：

- 金额保留公司原始披露币种与财年口径
- 同比按上一财年相同季度、半年或年度计算，不使用相邻期间环比
- 研发指标只采用公司明确单列披露的数据，缺失期间不推算；费用化研发、研发总投入、技术开发和公司自定义研发 KPI 会在说明中区分
- 历史序列以公司披露为主，SEC、交易所或证券行情结构化公开接口用于补齐与交叉校验
- 员工人数优先采用期末值；官方“约 X 万”等约数可以保留，期间平均人数仅在明确标注平均口径时使用，不反推期末人数
- 员工统计或合并范围显著变化时标注可比边界；非同期人数不移植到财年末
- 华为采用完整年度与正式债券半年报数据；半年序列覆盖 FY2019 H1 至 FY2026 H1，累计值直接展示，不拆分或推算季度

公司数据随前端版本离线发布，页面访问时不抓取财报。公司官网与定期报告是主来源；SEC Company Facts、交易所及证券行情结构化公开接口可用于补齐和交叉校验。单季度优先采用直接披露值；只有前三季度均可核验时，第四季度才由年度值扣减前三季度得到。结构化数据需通过年度与季度对账、连续财年、同比可比期和异常口径检查；与公司正式披露冲突时，以公司披露为准。

当前 52 家公司均保留至少 8 个年度（Arm 为上市以来 5 个财年）；华为与施耐德电气采用年度和公司直接披露的半年数据，其余公司的核心季度数据形成连续序列。华为 FY2019 H1 来自 2020 年半年报的正式可比栏，其余半年点采用当期报告；施耐德 Q1、Q3 仅披露收入，不据此补造季度利润。多数公司回溯至 FY2018，京东年度序列从 FY2017 开始并仅采用合并报表 GAAP 营业利润，拼多多连续季度序列从 FY2022 开始，默沙东和辉瑞因业务分拆重述从 FY2020 开始，IBM 从 Kyndryl 可比口径下的 FY2021 开始，强生从 Kenvue 可比口径下的 FY2023 开始，西门子季度序列从能源业务拆分后的 FY2021 开始，Arm 从首个可比季度 FY2023 Q1 开始。

研发年度序列已尽量补齐；比亚迪、宁德时代和三星等同时保留可核验季度值，Netflix 采用 Technology and Development，施耐德电气采用 total R&D costs / R&D cash costs。Visa、沃尔玛、亚马逊和 TCS 未持续单列可比研发指标，因此保留为空；SK 海力士 FY2018-FY2019 仅核实到总研发投入，不与后续费用化研发混用。员工人数只在口径和对应日期可核验时补充，不以半年数据平均拆分季度，也不补造未披露值。

维护时先运行 `npm run data:companies:check`：它按地区披露周期筛选待核查公司，串行比对 SEC 定期申报、近期业绩公告和同期间正式报告，并探测非美公司的官方报告归档。`--offline` 可仅运行本地周期检查，`--all` 可列出全部来源结果，`--strict` 可在发现报告候选或真实来源故障时返回非零状态；访问受限或请求失败会单独列出，不表示已经同步。美国公司可再运行 `npm run data:companies:draft -- --ticker=CSCO` 生成 SEC Company Facts 待审阅候选；命令只输出、不改写正式数据。完成数据录入后运行 `npm run data:companies:audit`，检查历史覆盖率、逐期来源、口径和非预期研发缺口。详细流程见 [公司数据维护](./COMPANY_DATA.md)。

财报日历只展示已披露报告或公司、监管机构、交易所正式确认的日期，保留原始公告链接；第三方预测日期不会标记为确定日程。

## 已知局限

- QDII 官方净值通常存在 T+1/T+2 延迟，境内外节假日差异会进一步影响披露日期
- 基金估算基于可获取的定期披露持仓、代理基准和行情，无法完整覆盖盘中调仓、现金、衍生品、费用和基金实际估值时点
- 持仓披露频率低于实际调仓频率，权重也会随市场变化，因此估算更适合观察方向
- 不同市场历史覆盖长度不同；部分公开接口可能限流、暂停或调整返回格式
- 日股和韩股公开行情可能延迟，港股个别代码需要在新浪与腾讯数据源之间切换
- Coin Metrics 社区数据适用于非商业用途，其他使用场景需自行确认许可

所有数据和估算仅供参考，不构成投资建议，基金净值以基金管理人正式披露为准。
