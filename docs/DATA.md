# 数据与估算

## 数据来源

| 数据 | 主要来源 | 保存方式 |
|---|---|---|
| A 股、美股、港股及期货行情 | 新浪财经、腾讯财经 | 当前快照与日线写入 SQLite |
| 台湾加权 | 台湾证券交易所（TWSE） | 官方月度历史写入 SQLite |
| 韩国 KOSPI、日韩个股 | Naver Finance | 日线与最近有效行情写入 SQLite |
| 基金净值、资料与持仓 | 天天基金、东方财富 | 净值、资料和季度持仓写入 SQLite |
| 比特币 | Binance、Coin Metrics | 当前行情与 UTC 日线写入 SQLite |
| 历史汇率 | 欧洲中央银行（ECB） | 换算为兑人民币参考序列后写入 SQLite |
| 公司经营数据 | 公司年报、半年报、季报 | 人工核对后随前端版本发布 |

公开接口没有长期稳定性承诺。解析失败、时间戳异常或价格越界时不会覆盖最近一次有效快照；页面状态与数据日期以实际响应为准。

## 市场行情口径

- A 股在交易时段展示实时行情；美股按北京时间晚间交易时段展示实时行情
- 港股和亚太指数非交易时段展示最近有效收盘价
- 纳指100、标普500、道琼斯、恒生指数和日经225现货闭市且对应期货活跃时，可在概览展示“期货 LIVE”参考
- 收益与风险页面使用已完成交易的现货或历史日线，不以盘中期货替代现货区间收益
- 市场状态结合交易所本地时区、午休、周末和已维护节假日判断

期货与现货存在基差、分红、利率、汇率和换月影响，只适合判断闭市期间方向，不等同于现货指数涨跌。

## 基金估算日期

估算先确定目标净值日，并保证价格和汇率按同一日期对齐：

- **待公布估值**：选择相关持仓市场均已完成交易的最近境内估值日，持仓收盘价与汇率冻结在该目标日
- **实时参考**：使用当前境内估值日；已收盘市场采用当日收盘，交易中市场采用当前行情，尚未开盘市场沿用最近收盘

最新官方净值、待公布目标日和实时参考目标日分别保存，避免将不同时点的数据混成一次估算。

## 计算公式

```text
股票累计涨跌 = 目标日价格 / 官方净值日价格 - 1
汇率累计涨跌 = 目标日汇率 / 官方净值日汇率 - 1

持仓人民币口径涨跌 = (1 + 股票累计涨跌) * (1 + 汇率累计涨跌) - 1
已披露持仓贡献 = sum(持仓权重 * 持仓人民币口径涨跌)

估算累计涨跌 = 已披露持仓贡献
             + (1 - 已覆盖权重) * 基准人民币口径涨跌
目标估算净值 = 最新官方净值 * (1 + 估算累计涨跌)
目标日涨跌 = 目标估算净值 / 上一估值日估算净值 - 1
```

默认基金按投资方向配置纳指100、标普500或对应宽基，补足未披露仓位。汇添富全球医疗（004877）使用全球医疗、恒生生物科技和低波动部分组成的复合代理；必要历史不完整时暂停生成估值，不用前十大持仓简单归一化替代。

## 校准与回测

worker 保存待公布估值快照，官方净值披露后记录误差。校准样本必须属于同一模型、同一季度持仓、同一残差基准和同一输入集合；仅在完整样本达到门槛，且时间外验证 MAE 至少改善 10% 时，才启用受限线性校准，否则保持原始模型。

## 公司经营数据

公司页面用于观察同一企业自身变化，不做跨币种绝对规模排名：

- 金额保留公司原始披露币种与财年口径
- 同比按上一财年相同季度、半年或年度计算，不使用相邻期间环比
- 研发费用只采用公司明确单列披露的数据，缺失期间不推算；费用化研发、研发总投入和公司自定义研发 KPI 会在说明中区分
- 历史序列以公司披露为主，SEC、交易所或证券行情结构化公开接口用于补齐与交叉校验
- 员工人数优先采用期末值；官方“约 X 万”等约数可以保留，期间平均人数仅在明确标注平均口径时使用，不反推期末人数
- 员工统计或合并范围显著变化时标注可比边界；非同期人数不移植到财年末
- 华为采用完整年度与正式债券半年报数据；半年序列覆盖 FY2019 H1 至 FY2026 H1，累计值直接展示，不拆分或推算季度

公司数据随前端版本离线发布，页面访问时不抓取财报。公司官网与定期报告是主来源；SEC Company Facts、交易所及证券行情结构化公开接口可用于补齐和交叉校验。单季度优先采用直接披露值；只有前三季度均可核验时，第四季度才由年度值扣减前三季度得到。结构化数据需通过年度与季度对账、连续财年、同比可比期和异常口径检查；与公司正式披露冲突时，以公司披露为准。

当前 50 家公司均保留至少 8 个年度（Arm 为上市以来 5 个财年）；除华为采用年度与直接披露半年数据外，其余公司的核心季度数据均形成连续序列。华为 FY2019 H1 来自 2020 年半年报的正式可比栏，其余半年点采用当期报告。多数公司回溯至 FY2018，京东年度序列从 FY2017 开始并仅采用合并报表 GAAP 营业利润，拼多多连续季度序列从 FY2022 开始，默沙东和辉瑞因业务分拆重述从 FY2020 开始，IBM 从 Kyndryl 可比口径下的 FY2021 开始，强生从 Kenvue 可比口径下的 FY2023 开始，西门子季度序列从能源业务拆分后的 FY2021 开始，Arm 从首个可比季度 FY2023 Q1 开始。

研发年度序列已尽量补齐；比亚迪、宁德时代和三星等同时保留可核验季度值。Visa、沃尔玛、亚马逊和 TCS 未持续单列可比研发费用，因此保留为空；SK 海力士 FY2018-FY2019 仅核实到总研发投入，不与后续费用化研发混用。员工人数只在口径和对应日期可核验时补充，不以半年数据平均拆分季度，也不补造未披露值。

维护时先运行 `npm run data:companies:check`：它按地区披露周期筛出即将到期的数据，并将美国公司的最新 10-Q/10-K 与本地截止日比对，只需核查候选公司。`--offline` 可仅运行日历检查，`--all` 可列出全部 SEC 比对结果，`--strict` 可在发现新财报时返回非零状态。美国公司可再运行 `npm run data:companies:draft -- --ticker=CSCO` 生成 SEC Company Facts 待审阅候选；命令只输出、不改写正式数据。完成数据录入后运行 `npm run data:companies:audit`，检查历史覆盖率、口径和非预期研发缺口。详细流程见 [公司数据维护](./COMPANY_DATA.md)。

财报日历只展示已披露报告或公司、监管机构、交易所正式确认的日期，保留原始公告链接；第三方预测日期不会标记为确定日程。

## 已知局限

- QDII 官方净值通常存在 T+1/T+2 延迟，境内外节假日差异会进一步影响披露日期
- 基金估算主要基于定期报告中的前十大持仓、代理基准和可获取行情，无法覆盖盘中调仓、现金、衍生品、费用和基金实际估值时点
- 持仓披露频率低于实际调仓频率，权重也会随市场变化，因此估算更适合观察方向
- 不同市场历史覆盖长度不同；部分公开接口可能限流、暂停或调整返回格式
- 日股和韩股公开行情可能延迟，港股个别代码需要在新浪与腾讯数据源之间切换
- Coin Metrics 社区数据适用于非商业用途，其他使用场景需自行确认许可

所有数据和估算仅供参考，不构成投资建议，基金净值以基金管理人正式披露为准。
